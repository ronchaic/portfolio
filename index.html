Situation

Management observed that employees were frequently accessing non-work-related websites — social media, gambling, and streaming platforms — during business hours. This behavior negatively affected productivity and consumed network bandwidth.

Task

Implement network restrictions to block these categories — enforcing company policy, minimizing productivity loss, and reducing the security risks associated with unverified websites.

Action

I implemented a multi-layered security approach on our FortiGate firewall:

  • Web Filtering: Configured a new Web Filter profile to block Adult/Mature Content, Bandwidth-Consuming (Streaming), and General Interest – Personal (Social Media) categories.
  • Application Control & QUIC: Built an Application Control profile targeting mobile apps, and blocked the QUIC protocol — forcing apps to fall back to standard TCP/HTTPS so the firewall can inspect and filter the traffic.
  • Policy Implementation: Applied both profiles to the main LAN-to-WAN policy, and verified NAT using the Outgoing Interface Address to mask internal IPs behind the WAN interface.
Result

Distractions were significantly reduced, management reported a noticeable improvement in focused work hours, and network bandwidth usage dropped by 20%.

Situation

Specific departments required access to work-related websites that were previously restricted — for example, Marketing needed Instagram and other social media platforms.

Task

Configure a separate policy for the Management and Marketing departments to allow social media access, distinct from the restrictive General Policy.

Action
  • Created new address objects under Policy & Objects → Addresses for VIP and Marketing devices, using MAC addresses to ensure persistent access even when IPs change via DHCP.
  • Grouped these users according to their respective departments.
  • Configured a custom Web Filter profile permitting traffic to social media and streaming sites.
  • Created separate firewall policies for these address groups — applying the custom Web Filter and Application Control while retaining standard AV and IPS from the general internal network.
Result

Marketing and VIP users now have secure, uninterrupted access to the social media and streaming platforms their roles require.

Situation

The IT Department initiated an upgrade to the data synchronization process between the Head Office server and remote retail stores — the objective being a seamless, high-speed, secure channel for data in transit.

Task

Implement an IPSec VPN as the primary connectivity solution on Fortinet firewalls so remote stores could securely update their in-house POS databases, plus an SSL/TLS VPN as a failover in case of IPSec unavailability.

Action
  • Primary (IPSec): Configured IPSec as the primary method, created local user accounts per store under User & Authentication → User Definition in a dedicated group, and enabled split tunneling so only Head-Office-bound traffic uses the VPN.
  • Backup (SSL-VPN): Configured SSL-VPN on the primary WAN interface on a non-standard port to avoid HTTPS conflicts, defined an IP address pool, and created a firewall policy granting internal access.
  • Endpoint: Installed FortiClient VPN on store POS terminals using the Head Office public IP as the remote gateway — IPSec primary, SSL-VPN secondary.
Result

Stores now enjoy seamless server access with automatic data synchronization. Inventory management is streamlined for inter-store stock transfers, and supervisors can view real-time sales reports — a significant improvement over the previous non-VPN method.

Situation

The company website experienced a critical spike in resource usage, causing high latency and frequent 503 Service Unavailable errors. Investigation identified a DDoS attack based on three key IoCs: unusual traffic spikes, server resource exhaustion, and suspicious source IPs.

Task

Immediately stop or mitigate the active DDoS attack and restore the website's availability.

Action
  • Deployed Cloudflare: Created a Cloudflare account to leverage its anti-DDoS capabilities.
  • DNS Migration: Imported the domain, scanned existing records, updated the registrar with Cloudflare nameservers, and set proxy status to Proxied to mask the origin IP.
  • Emergency Mitigation: Enabled Under Attack Mode to enforce a JavaScript browser challenge for all visitors, filtering malicious traffic.
  • Security Tuning: Enabled Bot Fight Mode, Browser Integrity Check to block fake user agents, and set the Minimum TLS Version to 1.3.
Result

The incident was resolved within 30 minutes. The attack was mitigated using Cloudflare's infrastructure, restoring full access — and the site now benefits from improved load times and a stronger security posture against future threats.

Situation

After deploying the corporate VPN, I observed unauthorized lateral movement from remote users. Store personnel were reaching the central server via UNC paths (SMB) to store personal files — treating a critical production server as common storage and introducing data-integrity risks, malware vectors, and accidental deletions.

Task

Enforce a Zero-Trust / Least-Privilege model for remote users:

  • Implement traffic shaping to guarantee bandwidth for POS transactions while mitigating tunnel saturation and DoS from compromised endpoints.
  • Restrict VPN access strictly to business-critical POS connectivity.
  • Block all unauthorized protocols (SMB, RDP, ICMP) to prevent file sharing and direct server access.
Action
  • Requirement Analysis: Worked with the dev team and confirmed the in-house POS app relies exclusively on TCP Port 1433 (SQL) for database sync.
  • Service Object: Created a FortiGate Service Object restricted to Port 1433 — whitelisting only POS traffic and implicitly denying everything else.
  • Traffic Shaping: Configured a High-Priority shaper for the POS service with a maximum bandwidth cap per user, a preventive control against bandwidth-based DoS.
  • Policy Implementation: Moved the POS-Only rule to the top of the sequence and disabled the legacy Allow-All rule permitting file access.
  • Policy-Based Shaping: Bound the priority rules to the VPN interface and POS service via a dedicated Traffic Shaping Policy.
Result

Security: Unauthorized file-server access via UNC paths was eliminated; all non-POS traffic (SMB, ping, RDP) is now blocked by default deny. Performance: POS traffic is prioritized over all other activity. Efficiency: Post-implementation testing showed a 10% improvement in data-sync speed from eliminating background noise.

Situation

While operations were stable, our security posture — stateful Layer 3/4 firewall rules plus standard endpoint AV — was becoming insufficient against modern threats. With sophisticated ransomware and encrypted malware on the rise, I identified a visibility gap where malicious traffic could bypass perimeter defenses hidden inside legitimate allowed ports.

Task

On my own initiative, upgrade the network's defenses with a perimeter Intrusion Prevention System — moving beyond port-based filtering to Layer-7 inspection to detect and block malicious payloads and command-and-control callbacks, without waiting for an incident to force the change.

Action
  • Sensor Configuration: Created distinct IPS sensors for Servers and Clients, using IPS Filters rather than manual signatures to automate discovery of new threats.
  • Resource Optimization: Defined specific Targets per profile (Server vs. Client) so the firewall only scans for relevant attacks, optimizing CPU usage.
  • Botnet Mitigation: Enabled Botnet C&C and Malicious URL blocking to automatically cut connections from infected endpoints to known attacker servers.
  • Network Segmentation: Segregated firewall policies for Client PCs, Servers, and special workstations — identical baselines with unique IPS definitions per segment.
  • Deep Packet Inspection: Enabled Deep SSL Inspection on server policies and deployed the Fortinet CA certificate to trusted endpoints, so the engine inspects the payload, not just headers.
  • Policy Ordering: Placed the specific Server policy above the general internet policy so critical server traffic is matched and inspected with priority.
Result

This self-initiated project established a proactive security layer that blocks network-based attacks standard AV often misses — reducing the attack surface by stopping lateral-movement attempts, and giving the IT team deep visibility into blocked threat traffic to keep the network hardened against evolving threats.
